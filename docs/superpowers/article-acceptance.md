# 조 제목 자동 번호 독립 인수 결과

2026-11-19. 최종 Linux ARM64 서비스 이미지 `sha256:2c4280a611ba5cbe8d93717b8093dd474c994f13555c7aa67a38ce59327bf12c`를 임시 루프백 포트에서 실행했다. Chromium 인수 검사 **3개가 57.06초에 통과**했다. 편집 단계별로 PDF 18개를 내려받아 대조했다. **18개 모두** 조판 응답, 화면에 표시된 미리보기, 다운로드 파일의 바이트가 일치했다. 시행을 맨 앞으로 옮긴 출력의 세 경로에서 얻은 SHA-256은 `99f64e726370c8bd7768cc05896a93e4edbbb70edae102043399be3941e1d445`였다.

## 편집 순서와 출력

로컬 편집기에서 배포한 서비스와 같은 소스로 만든 최종 테스트 이미지 `8d9ddc9dbc82`를 네트워크 없이 실행했다. 330개 검사가 통과했고, 호스트 전용 13개는 별도로 모두 통과했다. 이 중 10개는 기존 양식·목록·배포 동등성 회귀이고 3개는 이번 조 번호 인수 검사다.

| 배포한 편집기에서 저장한 예시 | PDF 지면 | SHA-256 |
|---|---|---|
| [편집 전 원고](../../proofs/articles/before.md) · [편집 전 PDF](../../proofs/articles/before.pdf) | 1쪽, 7개 조 | `c56a2da2e216fd2ddf08f412be1f0887dafae9b227d9bba539f36a6d2317de60` |
| [편집 후 원고](../../proofs/articles/after.md) · [편집 후 PDF](../../proofs/articles/after.pdf) | 1쪽, 9개 조 | `24ad3cf7a8f0d42f81c380ac607628b884e51c512b64c00144d62a3e5b473b95` |

두 예시의 모든 일반 조·가지조에서 첫 항의 표지와 본문을 함께 대조했다. 구두 기록의 두 항은 ①과 ②였고, 편집 후 고정한 제8조의9와 제10조에 이어 시행은 제11조였다. 예시의 SHA-256은 각각 화면의 미리보기와 같았다. [편집기에 다시 열 양식](../../proofs/articles/style.json)

입력의 일반 조 제목은 `제8조(목적)`, `제8조 정의`, `제2조 시행`이다. 숫자와 항 문구는 매 단계 다운로드한 PDF에서 쪽·줄 순서로 읽어 독립 기대값과 대조했다.

| 편집 | PDF에서 읽은 순서 |
|---|---|
| 목적·시행으로 시작 | 제1조(목적) → 제2조 시행 |
| 목적의 가지조 두 개 삽입 | 제1조(목적) → 제1조의2 → 제1조의5 → 제2조 시행 |
| 두 가지 사이에 정의 삽입 | 제1조(목적) → 제1조의2 → 제2조 정의 → 제2조의5 → 제3조 시행 |
| 시행과 소속 항을 맨 앞으로 이동 | 제1조 시행 → 제2조(목적) → 제2조의2 → 제3조 정의 → 제3조의5 |

각 조의 첫 항은 원고에서 `7.`로 시작했다. 목적에는 ① 솔바람, 하위 1. 안쪽기록, ② 풀잎이 따라왔고, 시행의 ① 햇살도 제목과 함께 이동했다. 별도 문단 뒤에 `4.`로 시작한 후속 목록은 ④를 유지했다.

## 가지조·고정·재개방

유일한 기준 조인 목적을 두 가지조와 시행 뒤로 옮기자, 앞에 놓인 가지조도 목적의 새 번호를 따라 제2조의2·제2조의5로 바뀌었다. 이어 둘째 가지와 일반 조인 시행을 각각 고정하자 **제3조의2 → 제8조의5 → 제2조 시행 → 제3조(목적)**이 출력됐다. 기준 조가 없는 발췌는 제31조의4를 유지했다.

고정 버튼으로 추가한 표식은 선택한 두 제목 끝에만 저장됐다. 원고를 다시 열고 가지조를 기준 조 뒤로 옮겨도 번호가 고정됐고, 해제 버튼을 누르면 새 순번을 따랐다. 자동 번호를 꺼도 조 제목의 고정 표식은 지면에서 숨겨졌고, 일반 제목·목록 안 제목·본문에 쓴 `{번호고정}`과 본문 인용 `제8조의2`는 그대로 읽혔다.

## 표현식과 기존 지면

- `[조 {한글}]`을 저장하고 다시 열면 제목에 표현식과 괄호 속 기울임이 적용됐다. 빈 표현식은 번호 없이 `(목적)`을 인쇄하면서 첫 항을 ①로 매겼다. 잘못된 표현식은 입력란에 한국어 오류를 표시했고 직전 PDF는 계속 열렸다.
- 동일한 ‘조’와 ‘단’ 사이의 공백을 실측했다. 첫 통합 이미지에서는 한 칸과 세 칸 모두 4.90959 PDF pt여서 실패했다. 수정한 이미지에서는 각각 **4.90959와 14.72877 PDF pt**였다.
- 기능 도입 전 이미지 `e95d0fc341ab`에서는 자동 번호 스위치가 없어 브라우저 검사 3개가 실패했다. 이때 수집한 비활성 PDF에서 제8조(목적), ⑦·⑧, 원래 본문 인용을 확인했다. 수정한 서비스에서 기본 양식과 다시 연 예전 양식 모두 쪽·줄·전체 글리프의 글꼴·크기·위치 서명이 같았다. SHA-256은 `9b6b955f385ae169fe4a35bea2c125a5f6200b91d7cf259e637d2a6578207111`이다.
