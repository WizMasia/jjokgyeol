# T12 구현 계획

기준 커밋 `bd86ec4`. [T12 설계](../specs/2026-11-20-style-suggestion-design.md)에 따라 지정된 워크트리에서 진행한다.

### Task 1: 모델과 검증

1. `tests/test_style_ai.py::test_partial_patch`에 두 예문과 직접 14pt 재편집을 넣는다. 잘못된 필드·목록·지면, 중복 지시, 여러 구간과 면 보존을 추가한다. 모듈 없는 상태의 실패를 확인한다.
2. `app/ai/style.py`에 로컬 모델 호출과 제한된 필드 → 편집 단위 patch 변환을 작성한다. 숫자·표현식·지면 검사와 고정 단위 변환은 기존 `Style`에 맡긴다. 설정은 `app/config/style-suggestion.json`에 둔다.
3. 같은 테스트가 통과하면 커밋한다.

### Task 2: HTTP 경계

1. 실제 ASGI 경로에서 성공, 잘못된 요청·제안, 용량 초과, 모델 장애, 시간 초과, 동시 작업 거부를 검사한다. 연결 전 실패를 확인한다.
2. `app/server.py`의 문서 작업 수명과 `jobs.isolated_job`을 사용해 작업자를 호출한다. 거부 응답은 기존 오류 형식과 no-store를 따른다.
3. HTTP 테스트와 Task 1 테스트를 함께 통과시킨 뒤 커밋한다.

### Task 3: 편집기와 지면 인수

1. 정상 편집기에서 필드 검토·취소·명시적 적용·직접 재편집·늦은 응답 보존을 단언하고 실패를 확인한다. 모듈은 별도 JS에 두고 화면에 연결한다.
2. 고정 대역 및 실제 모델을 같은 서비스 경로로 시험한다. 첫 요청의 16pt·14pt 재편집과 가운데 쪽 번호, 두 번째 요청의 본문 16pt·기존 제목/여백을 실제 PDF 글자와 좌표에서 확인한다.
3. 지정한 오프라인 Docker 러너에서 기능 및 관련 회귀를 실행한다. 실제 모델 인수는 별도 네트워크 허용 실행에서 수행한다. 명령·측정 결과와 설정 방법을 인수 문서에 기록하고 커밋한다.

검토 초점은 파일 열기와 늦은 응답의 순서, 기존 구간 규칙이 여러 행에 나뉜 경우, 모델 실패 시 부분 적용, 사용자가 편집한 원고·양식·기존 지면의 보존이다.

### 검증 기록

네트워크를 끈 Linux ARM64에서 모델 대역·API·브라우저 검사 26건을 통과했다. 별도 실모델 검사 1건에서는 로컬 Gemma 4 E2B가 위 두 요청을 처리했다. 16pt 본문은 PDF에서 15.940pt, 고정 18pt 제목은 17.933pt, 왼쪽 여백은 65.197pt였다. 쪽 번호의 중심은 209.764pt였다. 본문을 직접 14pt로 낮춘 PDF에서도 이 쪽 번호 위치가 유지됐고, “본문만 16pt로” 실행에서는 쪽 번호가 생기지 않았다.
