# 쪽결 작업 문서 (.jjok)

## 저장과 열기

원고와 적용한 출판 양식을 한 파일에 저장해 Docker 웹 편집기와 네이티브 앱에서 서로 열 수 있게 한다. ‘쪽결 문서 저장’에서 **교정 PDF 포함**을 선택할 수 있다. 새 문서에서는 켜져 있다. 이 설계에서는 실수로 PDF를 다시 보내는 일을 피하기 위해, 한 문서에서 끄고 저장하면 다시 열거나 저장할 때도 그 문서의 선택을 따른다. 다른 문서를 새로 만들면 기본값으로 시작한다.

저장을 누른 시점의 원고, 적용한 양식, PDF 포함 선택, 현재 선택된 교정본을 함께 확정한다. 저장하려고 새 조판을 시작하거나 진행 중인 조판을 기다릴 필요가 없다. 양식 창에서 아직 적용하지 않은 초안은 기존 양식 적용 절차를 따른다. 기존 원고·양식의 개별 저장과 PDF 다운로드도 계속 제공한다.

| 저장 시점 | 포함을 켰을 때 | 다시 열었을 때 |
| --- | --- | --- |
| 현재 원고와 양식으로 만든 지면을 표시 중 | 선택된 PDF 원본을 담는다 | 저장한 지면을 보여 준다 |
| 원고나 양식을 고친 뒤 이전 지면을 표시 중 | 수정된 원고와 양식, 같은 문서의 이전 PDF를 담는다 | ‘수정 전 교정본’으로 표시한다 |
| 첫 조판 전이거나 이 문서에서 성공한 조판이 없음 | 원고와 양식만 담고 포함 선택은 기억한다 | 미리보기를 갱신할 수 있다 |

어떤 경우든 포함을 끄면 파일에서 PDF가 빠진다. 이전에 PDF가 든 문서에 덮어쓸 때도 새 ZIP을 작성한다. 현재 화면에 보이는 지면은 계속 볼 수 있다. 포함을 켰는데 보관할 기존 PDF를 읽지 못했다면 저장 오류를 알리고 다시 시도할 수 있게 한다.

## 파일 형식

제안 확장자는 `.jjok`이다. `.jgx`는 이미 다른 프로그램에서 사용한다. [Juglans 공식 문서](https://docs.juglans.dev/guide/concepts.html)

표준 ZIP의 루트에 다음 항목을 둔다.

- `manuscript.md`에는 기존 원고 저장 경로가 내보내는 UTF-8 원문을 넣는다. 줄바꿈과 BOM을 포함해 개별 저장 결과와 같아야 한다.
- `style.json`에는 기존 양식 내보내기가 만든 정수 양식을 넣는다. 다시 열 때도 같은 양식 검증과 단위 변환을 사용한다.
- `manifest.json`은 형식 식별자 `jjokgyeol`, 버전 `1`, PDF 포함 선택을 기록한다. 교정본이 있으면 저장 당시 상태(현재·수정 전)와 선택한 조판 방식(규칙·모델·혼합)도 기록한다.
- 선택 항목 `proof.pdf`에는 마지막으로 편집기에 적용되어 표시된 교정본 한 개의 바이트를 그대로 넣는다. 비교용 다른 지면과 적용 전 시험 조판은 담지 않는다.

열 때는 필수 항목과 버전, 양식 및 PDF의 유효성, 실제 PDF 유무와 메타데이터의 일치를 먼저 확인한다. 두 앱이 같은 ZIP 크기·해제 용량 정책을 사용하고, 중복 항목은 거절한다. 검증과 기존 편집 내용 교체 확인이 끝나야 원고·양식·교정본을 함께 바꾼다. 저장된 지면은 모델 연결 없이도 볼 수 있고, 사용자가 미리보기를 갱신하면 그 결과로 교체한다. 저장 취소·실패나 저장 중의 추가 편집을 저장 완료로 처리하지 않는다.

## 검토한 방식과 확인 기준

저장 때마다 다시 조판하면 마지막 편집을 반영하지만, 사용자가 아직 보지 않은 줄바꿈을 교정본으로 전달할 수 있다. 항상 원고와 양식만 담으면 파일은 작지만 받는 사람이 발신자가 본 지면을 확인하기 어렵다. 선택한 방식은 마지막 지면을 기본으로 보관하고, 보내는 사람이 문서별로 제외할 수 있게 한다.

웹에서 저장한 문서를 네이티브에서, 네이티브에서 저장한 문서를 웹에서 열어 원고와 정수 양식의 왕복을 대조한다. PDF를 포함하면 저장 직전 선택한 교정본과 바이트가 같아야 한다. 포함 해제 후 덮어쓰기, 첫 조판 전 저장, 수정 전 지면 복원, 이전 문서의 늦은 조판 응답, 취소·오류 뒤 기존 편집 보존을 각각 확인한다. ZIP 처리 도구와 플랫폼별 파일 선택기 연결은 구현 계획에서 정한다.
