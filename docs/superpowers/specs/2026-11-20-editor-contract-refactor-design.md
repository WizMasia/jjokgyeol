# 편집기 입력과 서버 작업 한도 리팩터링 설계

기준은 `002170c`이다. [기존 리팩터링](2026-11-19-app-refactor-design.md)에서 도입한 출판 설정, 불변 `Style`, 정수 양식 파일, 공통 파일 열기 기능을 그대로 사용한다. 이번에는 그 뒤에 늘어난 호출자 사이의 세 가지 책임을 정리한다. [개발 원칙](../../../AGENTS.md)

| 대상 | 현재 확인한 구조 | 이번 변경의 경계 |
|---|---|---|
| 양식 오류 | 미리보기의 `render`와 저장의 예외 처리에서 조 번호·여백·활자 오류를 각각 배분한다. 미리보기는 관련 없는 오류에도 여백 표시를 지우고, 저장은 여백 오류일 때만 이를 갱신한다. | 필드별 표시 판단을 한 곳에 둔다. 상태 문구, 여백 표시를 지우는 시점, 오래된 응답을 무시하는 조건은 각 호출 경로의 계약으로 보존한다. |
| 십진수 비교 | `decimalKey`, `sameDecimal`, `compareDecimal`은 `editor.js`에 있지만 판형·여백·들여쓰기·활자·참고 서식에서 사용한다. | 기존 세 순수 함수를 한 파일에 두고 먼저 로드한다. 입력 철자, 단위 변환, 표시용 반올림, 서버의 정수 검증은 각각 기존 소유자가 맡는다. |
| 서버 작업 한도 | `DocumentJob`이 다섯 작업의 바이트 상한, 슬롯, 제한 시간을 서로 다른 메서드에서 선택한다. 조판과 원고 가져오기는 같은 슬롯을 사용한다. | 한 요청이 사용할 세 값을 한 번에 선택한다. 설정 원본, 공유 슬롯의 수명, 작업별 응답과 제한 시간의 적용 구간은 유지한다. |

조판기의 양끝맞춤, 어절 경계, 자간·공백 조절과 모델 후보 선택은 이 계획의 기준 동작이다. 입력 정리 후에도 같은 원고와 양식은 같은 조판 경로에서 같은 지면을 내야 한다. 기준판과 후보판에서 규칙 PDF끼리, 모델 PDF끼리 대조하고, 화면에서 선택한 결과와 다운로드 파일은 바이트로 대조한다. 일반 보고서, 9단계 계층 목록, 홀짝 줄 번호 양식도 이 기준에 포함한다.

각 변경은 단독으로 되돌릴 수 있다. 모듈 전체를 다시 나누거나 조판 알고리즘을 변경할 필요가 발견되면 해당 사례와 사용자에게 보이는 차이를 별도로 기록한다. [실행 계획](../plans/2026-11-20-editor-contract-refactor.md)
