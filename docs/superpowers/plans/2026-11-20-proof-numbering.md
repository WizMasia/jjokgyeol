# 계층 목록과 여백 줄 번호 구현 계획

[설계](../specs/2026-11-20-proof-numbering-design.md)를 따른다. Python Style과 목록 표지, 브라우저 편집기, LuaLaTeX의 실제 출력 줄을 연결한다. 저장 양식 호환성, 기존 PDF의 줄·쪽 위치, 실제 모델·규칙 조판에 공통으로 적용하는 것을 인수 조건으로 둔다.

- [x] 상위 순번을 쓰는 목록 표현식과 출판 프리셋을 구현한다. 중첩, 새 부모, 여러 자리, 명시한 시작값, 중괄호 이스케이프를 테스트한다.
- [x] 출판 양식에 선택한 여백을 저장하고 편집기 열기·저장·미리보기를 대조한다. 예전 양식을 열어 다시 저장할 때 표현을 보존한다.
- [x] 최종 줄에만 번호를 그림으로써 쪽 넘김, 긴 제목과 목록, 각주 제외, 양면 여백과 부족한 공간을 실제 PDF로 검사한다.
- [x] 두 기능을 함께 적용한 PDF와 이전 지면을 대조하고 화면에서 사용할 수 있는 빌드를 확인한다.


## 인수 기록

- PDF에서 새 부모로 바뀔 때의 `9.1.1. → 9.2. → 10. → 10.1.` 순서를 확인했다. 코드 예시 뒤의 실목록과 법령 조 제목 아래 목록도 별도로 비교했다.
- 왼쪽·오른쪽 숫자의 기준선과 6 TeX pt 간격, 쪽 넘김, 제목 틀, 각주·미주 제외를 검사했다. 한 자리에는 충분한 여백이 두 자리에서 부족해지는 경우도 확인했다.
- Chromium에서 계층 번호형과 오른쪽 줄 번호를 선택하고, 양식 저장·재개방 후 다운로드한 PDF를 미리보기 바이트와 대조했다. 기존 PDF 두 종류의 줄·글자 좌표 서명도 대조했다.
- [예제 원고](../../../proofs/numbering/manuscript.md)와 [양식](../../../proofs/numbering/style.json)을 설치된 편집기에서 조판했다. 규칙과 실제 모델 PDF에서 각각 오른쪽 줄 번호 1~16을 읽었고, 규칙 지면은 [배포 견본](../../../proofs/numbering/numbered.pdf)과 쪽별 글자 위치가 일치했다.
- 네트워크를 끈 전체 회귀에서 1,054건 통과, 61건 건너뜀, 기존 Starlette 경고 1건이었다. 최종 빌드 안에서 계층 목록·여백 줄 번호·양식 집중 검사 50건이 통과했다. 최종 서비스에 연결한 호스트에서 브라우저 인수 1건과 이전 PDF 좌표 서명 2건도 통과했다.
