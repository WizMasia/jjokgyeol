# T10 원고 가져오기 HTTP·편집기 구현 계획

**목표** 작업자로 격리한 변환 결과를 편집 중인 원고에 안전하게 연결한다. [보충 설계](../specs/2026-11-20-manuscript-import-editor-design.md)

### Task 1: 가져오기 요청과 격리

- [ ] `tests/test_import_api.py`에서 일반 HTTP POST의 원본 바이트·한글 파일명, 반환 키, 422 오류, Content-Length 및 스트리밍 크기 초과, 느린 업로드와 포화 후 재사용을 검사한다. Docker에서 404로 실패하는지 확인한다.
- [ ] `app/server.py`의 DocumentJob에서 설정된 원본 크기와 슬롯·기한을 적용하고 `app/import_worker.py`를 호출한다. 작업자가 메모리·파일 한도를 적용한 뒤 `app.importers.read.import_file(name, data)`만 호출하고 두 필드를 JSON으로 쓴다.
- [ ] 같은 테스트와 기존 작업자 쓰기·연결 해제 회귀를 Docker에서 실행한다.

### Task 2: 일반 편집기에서 새 .md 열기

- [ ] `tests/test_import_editor.py`에서 기존 호스트 Chromium으로 선택기, 이전 원고·저장 형식·미리보기·경고 보존, 지연 후 편집/새 열기/새 가져오기, 다시 저장을 검사한다. 선택기가 없는 실패를 먼저 확인한다.
- [ ] `app/static/index.html`에 선택기와 경고 목록을 추가한다. `app/static/editor.js`에서 기존 source 열기와 원고 적용 경로를 재사용한다. 응답 검증 뒤 텍스트로만 경고를 표시한다.
- [ ] `README.md`에 가져오기 절을 추가하고 새 브라우저 테스트와 기존 마크다운 열기·저장 회귀를 실행한다.

### Task 3: 다섯 형식 실물과 실제 조판 대조

- [ ] 라이브러리 담당자의 고정 표본을 사용해 호스트 브라우저와 Docker 서비스에서 TXT, HTML, DOCX, HWPX, HWP를 차례로 선택한다. 각 표본의 기대 텍스트를 저장한 .md와 실제 PDF에서 검사하고, 모든 경고와 원본 바이트를 대조한다.
- [ ] 라이브러리 커밋과 결합한 상태에서 새 HTTP·브라우저 테스트, 라이브러리 실물 대조와 기존 편집기·서버 회귀를 실행한다. 소유 파일만 커밋하고 브랜치와 검증 범위를 총괄에게 전달한다.

**검토 초점** 오류나 뒤늦은 응답의 부분 반영, 원본 이름으로 덮어쓰기, 사용자가 입력하는 동안의 토큰 취소, 경고를 통한 HTML 삽입, HTTP 시간 제한과 슬롯 해제, 기존 양식·미리보기 동작.
