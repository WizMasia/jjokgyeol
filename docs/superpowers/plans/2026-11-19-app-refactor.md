# 쪽결 앱 전체 리팩터링 구현 계획

**목표** 출판 설정, 서버 정책, 원고·양식 파일 처리를 각 책임 모듈에서 관리하면서 같은 입력의 PDF를 재현한다.

**구성** Python 표준 라이브러리로 설치 경로의 두 JSON을 읽는다. FastAPI가 편집 화면에 초기 양식을 제공하며, Lua와 브라우저는 기존 양식 모델에서 나온 값을 사용한다. [승인된 설계](../specs/2026-11-19-app-refactor-design.md)

**공통 조건** 기존 HTTP API와 정수 양식 파일, 마크다운 BOM·개행, Docker의 읽기 전용 앱 코드와 작업 격리를 유지한다. 각 담당자는 기존 테스트에 누락된 계약을 먼저 실패시키고 구현한 뒤 같은 검사를 통과시킨다.

**승인된 분담** Nash가 통합을 총괄한다. Bernoulli(출판 설정), Galileo(조판 엔진), Nietzsche(서버), Darwin(편집기)이 파일 소유권을 나눠 병렬로 구현한다. Gibbs는 제품 코드를 수정하지 않고 별도의 설치에서 설정 한 값의 전파와 기존 PDF의 보존 여부를 검증한다. 배포는 이 검증과 Nash의 통합 검토를 거친다.

- [x] **출판 양식** — `app/publication.py`, `app/config/publication.json`, `app/style.py`, `app/style_files.py`에 기본값·글꼴·조판 정책과 양식 변환을 모은다. `Style()`은 배포 기본 양식을 만들고 기본값 변경 후에도 기존 양식 파일을 읽는다. 서버에 `editor_bootstrap()`으로 `{defaults, fonts}`를 제공한다. `fonts`는 `{id, label}` 목록이다. 독립 기대값으로 기본값 변경, 허용 범위 변경과 정수 저장 왕복을 검증한다.
- [x] **엔진** — `app/typeset.py`, `app/tex/layout.lua`에서 Python이 준비한 `engine_policy()`로 regular/bold 파일과 제목 배율을 받는다. 단위, 글꼴 정체성과 정수 반올림을 확인하고 1sp 경계 및 실제 PDF 검사를 실행한다.
- [x] **운영 설정과 서버** — `app/operations.py`, `app/config/operations.json`, `app/server.py`, `app/jobs.py`에 설치 기준 설정을 연결한다. 양식 엔드포인트와 작업자는 공통 양식 인터페이스를 호출한다. 초기 HTML의 `<!--EDITOR_SETTINGS-->`에 JSON 스크립트 `#editor-settings`를 안전하게 삽입한다. 설정 로딩 실패, 요청 크기, 동시성, 제한 시간과 파일 한도를 확인한다.
- [x] **브라우저와 파일** — `app/static/`에서 양식 폼의 읽기·쓰기와 초기값 적용, 원고·양식의 파일 선택과 다운로드를 공통화한다. 초기 HTML과 동일한 방법으로 브라우저 테스트를 시작해 사용자 편집을 덮지 않는지 재검증한다. 최초 로드, 양식 오류와 회복, PDF 미리보기 URL 유지 및 교차 다운로드를 확인한다.
- [x] **통합과 배포** — Docker의 설정 포함 규칙을 갱신하고 같은 원고를 기본 양식과 기존 저장 양식으로 출력해 이전 문자 좌표 서명과 대조한다. 변경 설정이 화면·API·PDF에 함께 반영되는지와 독립 컨테이너 간 동등성을 확인한다. 전체 오프라인 테스트를 통과한 이미지를 기존 로컬 주소에서 실행한다.

## 인수 결과

Nash의 통합 검토와 Gibbs의 독립 인수를 통과했다. 최종 이미지에서 오프라인 186건과 호스트 전용 4건이 통과했다. 로컬 편집기를 이 이미지로 교체한 뒤 첫 화면, 기존 14pt 양식 열기, PDF 생성이 모두 HTTP 200을 반환했다. 실제 로컬 주소에서 받은 저장 양식 PDF는 2쪽·23줄·452자로, 변경 전의 지면 서명과 일치했다. [측정표와 재현 명령](../refactor-acceptance.md)
