# 마크다운 보고서 표 구현 계획

승인된 [표 조판 설계](../specs/2026-11-23-markdown-report-tables-design.md)를 웹·Mac의 공통 파서와 LuaLaTeX 경로에 적용한다. Superpowers의 subagent-driven-development 절차로 검증한다.

### 원고 파싱과 문서 구조

- [x] `tests/test_markdown_tables.py`에 셀 강조·정렬·빈 셀·이스케이프한 세로줄, 잘못된 머리행과 코드 예시에 대한 실패 테스트를 만든다.
- [x] `app/document.py`에서 기존 markdown-it 표 규칙을 사용한다. 표는 단일 블록이며 `rows[row][column]`에 인라인 목록을, `alignments`에 left/center/right를 담는다. 첫 행은 머리행이다.
- [x] 단독 표, 목록·제목과의 경계, 코드 블록, 표가 없는 기존 원고의 동작을 확인한다.

### 공통 PDF 조판

- [x] `tests/test_table_typeset.py`에서 실제 PDF 글자 좌표, 빈 셀, 긴 낱말, 강조·정렬, 반복 머리행, 쪽보다 긴 행의 마지막 셀, 뒤따르는 줄 번호를 검사한다.
- [x] `app/tex/layout.lua`와 표 전용 모듈에서 본문 글꼴로 셀을 조판한다. 좁은 열에는 필요한 폭을 주고 남은 폭을 긴 열에 배분한다. 평범한 행을 함께 옮기고 큰 행은 줄 단위로 나눈다.
- [x] 표에서 여백 번호와 모델 문단 후보를 생성하지 않는다. `app/typeset.py`와 영역별 양식 경로에서 표의 본문 적용과 메모 숨김을 검증한다.

### 문서 교환과 시험판

- [x] 웹에서 원고를 열고 PDF를 확인한 뒤 쪽결 문서로 저장한다. Mac 런타임에서 다시 조판해 셀과 지면을 비교한다. 기존 날짜, 본문, 목록 원고도 규칙·고정 모델로 대조한다.
- [x] 실제 설치 패키지에서 새 템플릿을 사용할 수 있는지 확인하고 웹과 Mac 로컬 시험판을 갱신한다. 검증된 변경만 로컬 main과 네이티브 브랜치에 병합한다.
