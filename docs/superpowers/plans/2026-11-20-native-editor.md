# 네이티브 편집 창과 첫 교정 PDF

**목표**는 웹판과 같은 편집 화면으로 원고와 양식을 열고 고친 뒤, 규칙 조판 지면을 확인하고 PDF를 저장하는 것이다. [설계안](../specs/2026-11-20-native-desktop-design.md) · [명령줄 교정본](2026-11-20-native-proof.md)

데스크톱 화면과 Windows 조판 검증은 독립적으로 작업한다. 두 결과가 모두 통과해야 Windows 편집기 시험판을 배포할 수 있다. 웹판은 기존 서버를 사용한다. 데스크톱은 로컬 화면과 동봉 작업자만 사용한다. 공개 릴리즈와 서명은 별도 단계다.

- [ ] **편집 화면**은 현재 HTML·CSS·편집 로직을 재사용한다. 데스크톱에서만 활성화되는 작은 연결부로 양식 변환, 조판, 저장을 Rust에 연결한다. 첫 화면은 기본 원고를 열고 자동 조판한다. 화면에 보이는 PDF 바이트를 그대로 저장한다. 스캔·참고 서식·모델 등 미연결 기능은 첫 개발판에서 표시를 제한한다.
- [ ] **데스크톱 작업자**는 종전 조판 계약에 더해 `--style-open`과 `--style-export`를 지원한다. 이 두 모드는 표준입력으로 받은 JSON을 기존 Style 모듈로 변환해 표준출력으로 반환한다. 잘못된 입력은 기존 필드·메시지로 알린다. 실제 양식으로 왕복을 시험한다.
- [ ] **Rust 창**은 `desktop/gui`의 Tauri 2 앱이다. 명령 `style_convert(action, body)`는 문자열 JSON을 작업자로 변환한다. `render_proof(source, style)`는 **저장 형식** 양식과 원고로 기존 Rust 실행기를 호출해 이진 PDF를 반환한다. `save_bytes(name, bytes)`는 사용자에게 저장 대상을 물어보고 같은 디렉터리의 임시 파일을 완성한 뒤 교체한다. 파일명은 제안 이름으로만 쓴다. 개발용 런타임 위치는 앱 실행 환경의 JJOKGYEOL_NATIVE_RUNTIME, 설치판 기본 위치는 앱 리소스의 runtime이다.
- [ ] **오프라인 미리보기**는 빌드 시 고정한 PDF.js와 worker를 앱 리소스에 담는다. 지면이 여러 쪽이면 스크롤로 모두 읽는다. 앱에서 여는 원고와 양식은 기존 파일 입력 동작과 한글·공백 경로를 시험한다.
- [ ] **통합**은 실제 macOS 창이 뜨고 기준 원고 편집 후 PDF 미리보기·저장이 되는지 확인한다. Windows는 해당 OS 작업자·Rust 실행기와 기존 웹 PDF의 독립적인 지면 비교를 병행한다. Linux·Windows 네이티브 창이나 설치 시험을 실행하지 않은 경우 결과표에 별도로 기록한다.
