# 쪽결 앱 전체 리팩터링 설계

2026-11-19 · 구현 승인

## 목적과 범위

같은 출판 정책이나 파일 처리 규칙을 바꿀 때 여러 언어의 코드를 함께 고쳐야 하는 문제를 줄인다. 사용자가 선택한 범위는 출판 양식, 브라우저 편집기, 서버 운영 설정, 파일 처리, LuaLaTeX 연결과 Docker 패키징이다. 현재 원고·저장 양식·HTTP API 및 조판 결과를 호환 기준으로 삼는다. 목록이나 가져오기 같은 새 기능은 이후 이 구조를 사용한다.

## 검토한 두 방식

- 출판 양식부터 정리하면 변경이 작고 지면 차이의 원인을 찾기 쉽다. 서버와 파일 처리의 중복은 다음 작업으로 이어진다.
- **선택한 방식은 앱 전체를 한 번에 인수하는 것이다.** 설정과 파일의 소유권을 함께 정리한다. 구현과 테스트는 책임별로 나누고 같은 이미지로 통합 검증한다.

## 설정과 소유권

| 정의 | 소유자와 소비자 |
|---|---|
| 출판 기본값과 정책 | 앱에 동봉하는 출판 설정 JSON에 A5 판형, 여백, 글꼴 ID와 표시명, 본문·행간, 들여쓰기, 자간, 공백 기본값과 허용 범위, 제목 크기 정책을 둔다. 양식 모델이 이 정의를 읽는다. 편집 화면에는 모델이 준비한 초기값·선택지를 전달하고, 조판기에는 검증된 값과 작업에 필요한 글꼴 정보만 전달한다. |
| 실제 글꼴 파일 | 기존 `runtime.lock`의 글꼴 ID와 regular/bold 파일을 재사용한다. 설정의 글꼴 ID와 잠금 파일의 일치 여부를 검사한다. 브라우저나 사용자 양식은 파일 경로를 지정하지 않는다. |
| 서버 정책 | 별도 운영 설정 JSON에 요청 크기(바이트), 동시 조판 수, 제한 시간(초), 작업 파일 크기 한도(바이트)를 둔다. 웹 프로세스와 격리된 조판 작업자가 설치 경로를 기준으로 같은 설정을 읽는다. 요청 작업 디렉터리에서 앱 설정을 탐색하지 않는다. |
| 단위·파일 계약 | 정수 sp, 분모 10000, UTF-8, 유니코드 문자 경계와 PDF 형식은 각 책임 모듈의 명명된 정의 및 기존 라이브러리를 쓴다. 양식에 입력하는 숫자와 실제 PDF 좌표의 단위 차이를 보존한다. |

설정은 시작할 때 읽고 검증한다. 잘못된 기본 양식, 누락된 글꼴, 0 이하의 운영 한도는 항목을 식별할 수 있는 오류로 드러난다. 공개 편집 화면에는 출판용 데이터만 전달한다. 실행 중 설정 재적용이나 관리자 화면은 요구 범위에 없다.

이번 배포는 허용 범위 70~130%를 유지한다. 기본값을 바꾸어도 기존 파일의 명시값이 우선한다. 운영자가 추후 허용 범위 자체를 줄이면, 새 한계를 벗어난 값은 열기·미리보기·저장에서 같은 필드 오류로 안내하는 방안을 제안한다. 예를 들어 상한을 120%로 바꾼 설치에서는 130% 파일의 원문을 보존하고 오류를 표시한다. 값을 자동으로 낮추면 재출력 때 줄바꿈이 달라질 수 있다.

## 공통 인터페이스

- **양식.** 기존 불변 `Style` 객체에 대해 기본 양식 생성, 편집값 적용, 저장값 검사, 편집값·저장값 출력을 한 모듈의 공개 인터페이스로 제공한다. 미리보기·내보내기·양식 열기가 이를 재사용한다. 편집기 단위(mm·pt·%)와 저장 단위(sp·비율 정수)의 입력 경로는 명시적으로 구분하고, 기존 호출자가 쓰는 진입점은 호환한다.
- **편집 폼.** 하나의 폼 인터페이스가 이름이 붙은 컨트롤의 읽기와 쓰기를 모두 맡는다. 배열 필드 순서와 십진수 원문을 보존한다. 최초 HTML 응답에 출판 설정을 포함해 사용자가 편집을 시작하기 전에 기본값을 적용한다.
- **파일.** 마크다운과 양식 JSON은 각자 인코딩·검증을 맡는다. 브라우저의 파일 선택, 비동기 열기 상태, 파일 내려받기와 임시 URL 수명 등 같은 동작은 공통 인터페이스를 쓴다. PDF 미리보기 URL은 화면 교체까지 유지하며 내려받기 후에도 같은 지면을 보여 준다. 마크다운의 BOM·줄바꿈, 양식 저장 클릭 시점의 값, 잘못된 파일을 연 뒤의 복구를 유지한다.
- **조판과 서버.** 서버는 요청 경계에서 운영 한도와 오류 응답을 관리한다. 조판 작업자는 검증된 원고·양식과 설치 설정으로 엔진 입력을 만든다. Lua는 실행 시 받은 설정으로 글꼴과 제목 크기를 정하고, 줄 폭 측정과 출력은 기존 정수 연산 인터페이스를 그대로 쓴다. 기존 작업 격리·시간 제한과 허용 글꼴 경계를 유지한다.

## 인수 기준

1. 출판 설정의 기본 글자 크기나 글꼴을 바꾼 테스트에서 빈 양식을 사용한 API, 첫 편집 화면, PDF가 같은 값을 사용한다. 운영 설정의 한도를 바꾼 테스트에서 실제 해당 요청 경로가 그 값을 적용한다.
2. 기존 정수 양식 예시를 열고 다시 저장한 내용이 같다. 십진 입력, 음수 절반 반올림, 최소 1sp 폭과 오류 응답의 필드·상태가 유지된다.
3. 원고와 양식 동시 열기, 느린 응답, 다운로드 직전 수정, 실패 후 재시도를 브라우저에서 검증한다. 파일 형식마다 기존 저장 내용을 확인한다.
4. 동일한 원고와 양식으로 리팩터링 전후 PDF의 쪽 수, 줄 끝, 글꼴, 문자 좌표, 각주 위치를 대조한다. 새 이미지에서 미리보기 바이트와 다운로드 바이트가 같은지도 확인한다.
5. Docker 빌드에 두 설정 파일을 포함하고 고정 Linux ARM64 이미지 안에서 외부 네트워크 없이 전체 회귀 검사를 실행한다. 별도 컨테이너 간 지면 일치 검사도 반복한다.
