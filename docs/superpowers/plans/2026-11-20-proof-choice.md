# 모델·규칙 조판 선택 인수

1. 서버 측에서 실측한 규칙 PDF 및 모델 PDF를 같은 작업에서 반환하는 검사를 먼저 실패시킨다. 후보 수집을 재사용하고 단일 PDF 계약, 폴백 및 작업 자원 회수를 검증한다.
2. 브라우저에서 한 요청으로 받은 두 결과의 모델 우선, 수동 전환, 선택한 PDF 다운로드, 원고·양식 변경과 늦은 응답 처리를 검사한 뒤 화면을 구현한다.
3. 실제 배포 환경에 연결한 브라우저에서 두 PDF의 바이트, 실제 모델 사용, 표시 및 다운로드를 확인한다. 모델 미연결 지면과 기존 참고 양식 적용도 검증하고 문서·비공개 원격 저장소에 반영한다.

## 실제 지면 확인

로컬 Gemma를 연결한 브라우저에서 ‘풀잎 사이 Dew 은빛 이슬’ 원고를 한 번 갱신했다. 모델 지면의 첫 줄은 ‘Dew’로, 규칙 지면의 첫 줄은 ‘은빛’으로 끝났다. 모델 → 규칙 → 모델을 고를 때 추가 렌더 요청은 0회였다. 매번 화면에 연결된 PDF와 다운로드 파일을 응답에서 선택한 부분과 바이트 단위로 대조했다. 두 지면 모두 각주 ‘아침 수집함.’을 보존했다.

기존 단일 PDF API의 모델·규칙 출력과 새 비교 응답을 고정 양식 및 양끝맞춤 원고 각 한 편에서 대조했다. 네 지면 모두 인쇄된 글자와 좌표가 일치했다. 모델을 적용하지 못한 경우, 일부 문단에서 규칙으로 복귀한 경우와 참고 양식의 시험 조판·적용은 개별 검사에서 다룬다. 본문 11pt를 16pt로 바꾸고 직접 14pt로 고치는 실제 모델 시험에서도 제목 18pt 및 가운데 쪽 번호가 유지됐다.

규칙으로 인쇄해 보관한 보고서 11pt·16pt PDF는 편집기에서 규칙을 고르면 이전 글자·좌표와 일치했다. 모델 지면도 제목, 본문, 각주, 기관명, 쪽 번호의 크기와 내용을 보존했다. 테스트 이미지 64개 모듈에서 1,029건을 통과했다. 외부 환경이 필요한 검사 등 59건을 이 실행에서 건너뛰었고, 별도 브라우저와 실모델로 지면 선택·출판 양식·참고 서식·주석 등을 검사했다. 배포한 앱 파일 51개의 SHA-256이 저장소와 일치했다.
