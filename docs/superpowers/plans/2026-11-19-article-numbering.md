# 조와 가지조 자동 번호 구현 계획

> **For agentic workers:** Use superpowers:subagent-driven-development. Nash가 통합하고 별도 검증 담당자가 브라우저와 PDF를 대조한다.

**목표** — 원고 표기는 유지하면서 제목과 항 번호를 조판 시점에 계산한다. [설계](../specs/2026-11-19-article-numbering-design.md)

**구성** — 현재 MarkdownIt → Python 문서 블록 → LuaLaTeX 흐름과 기존 목록 표현식을 사용한다. 편집기는 원고와 양식을 전달하고 서버가 양쪽 출력의 번호를 한 번 계산한다.

## 공통 조건과 검토 초점

기존 양식 JSON의 생략 필드와 기존 PDF 지면을 보존한다. 출판 기본값은 `app/config/publication.json`이 소유한다. 매 담당자는 해당 회귀 사례가 실패하는 것을 확인한 뒤 구현한다.

특히 ① 일반 조 사이에 가지조만 추가한 경우, ② 기준 조와 떨어져 이동한 가지조, ③ 고정한 조와 발췌, ④ 강조·괄호·본문 인용 보존, ⑤ 순번 7로 시작하는 첫 목록과 그 하위 목록을 확인한다.

## 작업 분담

- [x] **양식과 API.** `tests/test_list_styles.py`에 생략된 양식의 저장 호환성, 사용자 표현식 왕복, 잘못된 표현식의 필드 오류를 추가한다. `app/publication.py`·`app/style.py`가 선택 필드 `article_expr`를 검증하게 한다. 생략하면 기존 동작이고, 켤 때 쓸 표현식은 편집기 설정의 `default_article_expr`에서 읽는다.
- [x] **원고와 조판.** `tests/test_articles.py`에 기본·삽입·이동·발췌·고정 사례를 먼저 쓴다. `app/articles.py`에서 원고 번호를 식별하고 일반 조에 할당한 출력 번호로 가지조를 해석한다. `app/typeset.py`에서 복사한 블록에 이를 적용한 후 기존 목록 표지 계산을 호출한다. 각 조에서 첫 최상위 그룹의 순번만 1부터 보정한다. 제목 끝의 독립된 `{번호고정}`을 고정 표식으로 쓰고 지면에서 숨긴다.
- [x] **편집기.** `tests/test_editor.py`에서 자동 번호·표현식·선택한 조의 번호 고정/해제·파일 왕복을 검증한다. `app/static/index.html`과 `editor.js`에서 고정 동작을 원고에 반영한다. 고정 버튼은 서버의 조판용 마크다운 판정을 공유하는 `POST /api/article/pin`을 사용한다. 편집 중 늦게 온 응답이 원고를 덮어쓰는 경우, 여러 줄 제목의 표식 해제, 코드 예시·목록 내부 제목을 회귀 검사한다. 직접 입력한 같은 마크다운 표기도 동작한다. 본문이나 일반 제목의 리터럴은 보존한다.
- [x] **독립 인수.** `tests/test_article_acceptance.py`에서 실제 편집기로 초기 원고 → 가지조 삽입 → 일반 조 삽입 → 순서 이동 → 번호 고정을 수행한다. 매 단계 미리보기와 다운로드 바이트가 일치하고, PDF에서 추출한 제목과 각 제목 아래의 ①가 독립적으로 지정한 기대값과 일치해야 한다. 원고·양식 재개방과 기존 비활성 지면도 대조한다.
- [x] **통합과 배포.** 최종 Docker 이미지에서 기존 검사와 독립 브라우저 검사를 실행한다. `proofs/articles/`에 편집 전후의 마크다운과 실제 출력 PDF, 재현용 양식을 둔다. README·제품 스펙에 사용법을 반영하고 로컬 편집기를 열어 확인한다.
