# 제목줄 서식과 개별 문단 정렬

보고서에서는 문서 제목을 가운데에 두고, 작성일과 작성자를 오른쪽에 두며, 이후 본문은 원래 양식으로 이어 쓰는 경우가 있다. 웹과 Mac 편집기에서 제목 단계별 서식을 한 번 지정하고, 필요한 문단 하나만 원고에서 바로 조정할 수 있게 한다.

## 선택한 방식

제목 전체에 반복해서 적용할 값은 출판 양식에 둔다. 개별 문단의 정렬을 양식에 줄 번호로 기록하면 원고를 편집할 때 대상이 달라지고, `.md`만 복사하면 설정이 사라진다. 사용자가 선택한 방식은 해당 문단 바로 앞에 쪽결 전용 HTML 주석 한 줄을 저장하는 것이다. 원고를 옮기거나 작성일을 고쳐도 표시가 대상과 함께 움직인다. 다른 Markdown 뷰어가 HTML 주석을 숨기는 경우에는 본문만 그 뷰어의 기본 정렬로 보인다.

## 사용 방법

- **제목 전체**는 ‘설정 → 역할별 글자 모양’에서 제목 1~6 중 하나를 고른다. 기존 글꼴·크기·굵기·색 및 제목 1의 틀 설정과 함께 ‘정렬’을 지정한다. 선택지는 기본·왼쪽·가운데·오른쪽이다. ‘기본’을 선택하면 해당 단계의 정렬 지정만 해제한다.
- **문단 하나**는 원고에 커서를 놓고 ‘문단 정렬’에서 양식 따르기·왼쪽·가운데·오른쪽을 선택한다. 제목 한 곳에도 쓸 수 있다. 문단 중 일부를 선택해도 문단 전체에 적용한다. 컨트롤은 현재 문단에 직접 지정한 값을 보여준다. 제목 양식에서 가운데가 왔으면 개별 컨트롤에는 ‘양식 따르기’가 표시된다.
- 첫 버전은 **한 번에 한 블록**을 편집한다. 빈 줄, 서로 다른 블록에 걸친 선택, 목록·표·인용문·코드·각주 정의를 가리키면 정렬을 적용할 수 없는 이유를 알려 준다. 선택의 끝이 다음 줄 맨 앞이면 직전 줄까지만 선택한 것으로 판정한다. 정렬 주석 위의 커서는 주석이 가리키는 문단에 속한다.
- 편집기는 주석을 자동으로 넣거나 바꾼 뒤 원래 편집하던 글자에 커서를 유지한다. ‘양식 따르기’는 연결된 주석을 지운다. 한 동작은 한 번의 실행 취소로 되돌릴 수 있다. 같은 값을 다시 고르면 원고를 수정 상태로 만들지 않는다.

예를 들어 제목 1의 양식 정렬을 가운데로 지정하고 작성자 문단에서 오른쪽을 고르면 다음 원고에서 제목과 작성자가 각각 원하는 위치에 놓인다.

```markdown
# 현장 점검 보고서

<!-- 쪽결 정렬=오른쪽 -->
2026. 11. 23.  현장 점검팀

## 보고 요지

점검 결과를 보고합니다.
```

## 원고와 양식의 저장 계약

- 원고 표시는 첫 열에서 시작하는 독립된 한 줄이다. 정확한 철자는 `<!-- 쪽결 정렬=왼쪽 -->`, `<!-- 쪽결 정렬=가운데 -->`, `<!-- 쪽결 정렬=오른쪽 -->`이다. 빈 줄 없이 이어지는 최상위 일반 문단 또는 제목 하나에 붙는다. 여러 원고 줄로 구성한 문단과 밑줄식 제목도 한 블록으로 판정한다.
- 적용 가능한 주석은 앞 문단의 끝과 다음 블록의 시작을 구분한다. 중복된 정렬 주석이 연속하면 마지막 값이 유효하다. 편집기로 값을 바꾸면 한 줄로 정리하고 해제하면 전부 지운다. 앞에 별도 문단이 있고 빈 줄 없이 이 주석만으로 구분한 수기 원고에서는 해제할 때 두 본문이 합쳐지지 않도록 필요한 빈 줄 하나를 남긴다.
- 대상 없이 끝난 주석, 빈 줄로 분리된 주석, 알 수 없는 값, 코드 예시나 표 셀 안의 표시는 편집 명령으로 해석하지 않고 기존 원고 처리 규칙을 따른다. 유효한 주석은 PDF 본문·제목·쪽 머리말·문단 번호에 들어가지 않는다. 원고 편집과 조판에서 같은 블록 경계를 쓰며, 조 제목 고정 등 기존 편집 명령은 원본 줄 위치를 계속 사용한다.
- 제목 단계 값은 기존 `Style`의 `text_styles.heading1`~`heading6`에 선택 속성 `align`으로 두고 `left`, `center`, `right`를 허용한다. ‘기본’은 필드 생략이다. 지원하지 않는 값이나 역할은 기존 양식 검증 경로에서 필드 단위로 알린다. 개별 정렬은 `.md`에, 단계별 기본은 양식 JSON에, 둘 다 `.jjok`에 보존한다. 이전 파일을 열었을 때 생략된 값은 원래 조판 방식을 따른다.

## 지면에 적용하는 규칙

직접 지정한 정렬이 최우선이고, 제목이면 해당 단계의 양식, 그다음은 기존 조판 기본값이다. 정렬값이 없는 틀 제목은 기존의 가운데 배치를 따른다. 틀에 정렬을 지정하면 틀 안쪽 폭을 기준으로 삼는다. 다른 블록은 해당 쪽의 실제 본문 폭을 써서 맞쪽 여백도 반영한다.

명시적으로 정렬한 블록은 첫 줄과 이후 줄의 양식 들여쓰기를 모두 0으로 두고, 각 줄을 자연스러운 어절 간격으로 배치한다. 가운데면 각 줄의 중심이, 오른쪽이면 각 줄의 오른쪽 끝이 일치하며 마지막 줄도 같다. 같은 원고·양식의 규칙 조판과 모델 조판은 해당 블록에서 동일한 줄바꿈과 정렬을 사용한다. 모델의 본문 후보 선정에서도 해당 블록을 제외한다. 주위 본문은 원래의 들여쓰기와 문단 배치, 모델 선택을 따른다. 글자 강조·각주·조 제목 번호·줄 번호의 의미와 제목이 다음 문단과 함께 넘어가는 조판 규칙은 유지한다.

## 구현 경로와 검증 기준

- 웹과 Mac의 공용 원고 편집기 및 설정 창에 연결한다. 원고 범위 처리는 기존 조 제목 편집 코드의 줄 위치 계산을 재사용하고, 양쪽이 같은 파서 판단을 받도록 웹은 앱 API, Mac은 네이티브 명령을 통해 로컬 워커를 호출한다. Mac에서 서버 연결 없이도 문단을 정렬할 수 있어야 한다. 조판에는 공용 Markdown 파서와 LuaTeX, 저장에는 기존 원고·양식·문서 코덱을 사용한다. 비동기 편집 결과는 요청 시의 원고와 선택이 유효할 때만 적용한다. 주석 삽입·해제는 수정 여부 및 미리보기 갱신에 일반 원고 편집과 같이 반영한다.
- 위 보고서 예시를 좁은 판형과 맞쪽 여백에서 실제 PDF로 검증한다. 두 줄로 감긴 작성자의 각 줄 오른쪽 끝, 일반 제목과 틀 제목의 각 줄 중심, 왼쪽으로 직접 바꾼 제목 하나 및 앞뒤 일반 문단의 글자 좌표를 확인한다. 같은 입력으로 규칙·고정 모델 결과를 비교하고, 원고 주석과 제목 정렬을 각각 해제한 결과는 변경 전 기준 PDF와 대조한다.
- 웹과 Mac에서 직접 지정·변경·해제·실행 취소, 정확한 줄바꿈과 선택 범위, 코드 안의 예시, 기존 파일 열기를 검증한다. 웹에서는 조 제목 고정 명령과 함께 사용하고, Mac에서는 오프라인 편집을 확인한다. 주석을 편집한 범위 밖에서는 원본 줄 끝과 BOM도 보존한다. 원고와 양식 JSON을 각각 저장해 다시 열고, PDF 포함 및 제외로 저장한 `.jjok`을 다른 편집기에서 열어 같은 정렬로 새 PDF를 생성하는지도 확인한다.

한 번에 한 블록을 대상으로 하는 범위와 명시적 정렬에서 들여쓰기를 해제하는 규칙은 이 설계에서 제안한 기본 동작이다. 컨트롤의 배치와 내부 함수 구성은 기존 편집기 관례에 맞춘다.

## 추가 요청을 반영한 0단계와 글자 크기

역할 선택 맨 위의 ‘0단계 본문’은 Markdown 표시가 없는 보통 문단이다. 본문에도 왼쪽·가운데·오른쪽의 기본 정렬을 지정할 수 있다. 목록·표·제목은 본문의 명시적 정렬을 상속하지 않는다. 개별 문단 정렬이 우선한다. 0단계의 글자 크기와 글꼴은 기존 본문 설정과 같은 값이며, 1~6단계는 각각 독립적으로 크기를 지정하거나 본문에 대한 기존 배율로 복원할 수 있다. 크기를 두 곳에 저장하지 않는다. 이전 양식을 열기만 해서는 정밀도나 지정 여부가 바뀌지 않는다.
