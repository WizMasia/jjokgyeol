# 쪽결 디시전 모델 연결

웹 편집기와 네이티브 앱에서 사용자가 선택한 모델로 문단의 줄바꿈을 결정한다. 기존 조판기가 허용한 후보를 만들고, 모델은 그중 하나의 ID를 반환한다. 사용자가 선택한 Codex 인증 방식은 OpenAI API 키다.

## 설정과 사용

편집기의 설정에서 조판 방식을 규칙 또는 모델로 선택한다. 모델을 선택하면 API 형식, 모델명, 서버 주소와 필요한 API 키를 입력할 수 있다. 공식 서비스의 주소는 미리 채운다. 사용자 지정 서버는 아래 형식 중 하나를 선택해 연결한다. 같은 주소에서도 모델 이름을 바꿀 수 있다.

‘연결 확인’은 짧은 예제 후보를 보내 유효한 ID를 돌려받는지 검사한다. 유료 API에 소량의 요청이 발생할 수 있음을 버튼 곁에 표시한다. 설정을 열거나 모델명을 입력하는 것만으로는 호출하지 않는다. 적용하면 다음 미리보기부터 선택한 모델을 사용한다. 모델 정보는 원고의 출판 양식이나 문서의 일부가 아니다.

첫 버전에서는 사용자가 입력한 연결 정보를 웹은 탭, 데스크톱은 편집기 실행 세션 동안 유지한다. 키는 앱이 실행되는 동안 메모리로 전달한다. 설정 재열기, 취소, 모델 교체, 키 지우기를 지원하고 적용 전 변경은 기존 연결에 영향을 주지 않는다. 서비스나 주소를 바꾸면 이전 주소의 키를 새 주소에 보내기 전에 새로 입력받는다. 두 웹 탭이 다른 모델을 사용해도 서로의 연결에 영향을 주지 않는다. 기존 운영자 설정을 쓰는 웹 설치는 사용자가 변경하기 전까지 종전대로 동작한다. 다른 설치의 초기값은 규칙 조판이다.

## 지원할 API 형식

| 형식 | 요청과 지원 범위 |
| --- | --- |
| OpenAI Responses | `POST /v1/responses`. OpenAI API로 제공되고 계정에서 접근 가능한 GPT 또는 Codex 모델 ID를 입력한다. Codex CLI를 실행하거나 구독 로그인을 요구하지 않는다. |
| OpenAI Chat Completions 호환 | `POST /v1/chat/completions`. 사용자 지정 기본 주소 및 선택적 키로 호환 서비스와 로컬 서버를 연결한다. |
| Google Gemini | Gemini Developer API의 `generateContent`를 호출한다. |
| Anthropic Claude | 버전 및 인증 헤더를 지정해 Messages API의 `POST /v1/messages`를 호출한다. |
| Ollama 기본 API | `POST /api/chat`에 비스트리밍 요청을 보낸다. OpenAI 호환 경로를 쓰는 Ollama도 지원한다. |

프록시 하나를 별도로 설치하는 방식과 제공자별 공식 SDK를 모두 동봉하는 방식을 검토했다. 쪽결에서 필요한 기능은 기한 안에 한 번 요청하고 짧은 답을 읽는 것이다. 기존 Python 작업자에 API 형식별 요청 작성과 응답 읽기를 두고, 후보 검증은 한 곳에 둔다. 자체 학습 모델이 생기면 같은 선택 인터페이스를 로컬 함수로 구현할 수 있다.

호환 서버 URL은 API 버전을 포함할 수 있는 기본 주소로 받는다. 예를 들어 `https://example.org/proxy/v1`에 Chat Completions를 선택하면 `/proxy/v1/chat/completions`로 보낸다. 키 없는 로컬 서비스도 쓸 수 있다. 단순 채팅 모델에는 일반 텍스트로 JSON 답을 요청하고 스키마 지원을 선결 조건으로 두지 않는다. API 형식이 일치해도 예제에서 허용한 후보 ID를 안정적으로 반환할 수 있어야 한다.

## 조판, 전송과 오류 처리

- 모델에 보내는 정보는 후보 ID와 기존 `features()`가 허용한 줄바꿈 측정값이다. 요청 바디에 원고 본문, 문서 경로, PDF를 넣지 않는다. 응답은 완결된 텍스트 답에서 읽은 후보 ID 하나로 제한한다. 미완료, 거절, 빈 응답, 목록에 없는 ID는 조판에 적용하지 않는다. 구조화 응답이 필수가 아닌 호환 서버에서도 JSON 답을 검증한다.
- 웹에서는 편집기와 같은 출처의 서버, 네이티브에서는 앱의 작업자가 모델을 호출한다. Docker 웹판은 공식 서비스와 운영자가 명시적으로 등록한 기본 주소만 사용한다. 네이티브 앱에서는 사용자가 직접 지정한 HTTPS 서버와 같은 기기의 루프백 HTTP 서버를 허용한다. 두 환경 모두 리디렉션으로 다른 서버에 자격 증명을 전달하지 않는다. 키는 URL, 로그, 임시 조판 파일, PDF나 `.jjok`에 기록하지 않으며 TeX 자식 프로세스에도 전달하지 않는다.
- 기본 규칙 PDF를 먼저 확보한다. 일부 문단의 선택이 실패해도 기한 안에 재조판과 검증까지 마친 경우에만 혼합 결과를 표시한다. 전체 모델 작업의 기한이 끝나면 성공한 선택이 일부 있어도 이미 확보한 규칙 PDF를 반환한다. 기존 시간 제한 회귀 검사와 같은 동작이다. 완전히 규칙으로 돌아왔을 때와 일부 문단만 모델을 사용했을 때를 화면에 구분해 표시한다. 인증 실패, 모델명 오류, 시간 초과 등은 키나 서버의 원문 응답을 드러내지 않고 식별한다. 이전 설정·원고로 시작한 늦은 응답은 새 지면을 덮어쓰지 않는다.
- 네이티브의 기존 규칙 전용 출력과 CLI 호출은 계속 지원한다. GUI 모델 경로에서는 동봉된 엔진·글꼴을 이용하고 웹과 동일하게 실제로 적용된 방식 및 비교용 규칙 PDF를 돌려준다. 운영체제에 따라 달라지는 프로세스 종료 처리는 기존 Rust 감독 코드와 연동한다.

## 완료 기준

다섯 API 형식의 요청 경로·인증·응답 형식과 실패 처리를 로컬 HTTP 테스트로 검증한다. 설정에서 연결 후 미리보기를 갱신하고 모델이 고른 후보가 실제 PDF의 줄 끝에 반영되는지 웹·네이티브 진입점에서 확인한다. 연결 실패와 시간 초과 후 규칙 PDF 보존, 설정 변경 중 늦은 응답, 두 탭의 독립성, 기존 문서의 PDF 왕복을 검사한다. 실제 서비스 검증은 해당 모델과 자격 증명으로 수행한 호출을 구분해 기록한다.

공식 자료는 [OpenAI Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses), [OpenAI Codex 모델 예](https://developers.openai.com/api/docs/models/gpt-5.3-codex), [Gemini](https://ai.google.dev/api/generate-content), [Claude](https://platform.claude.com/docs/en/api/messages/create), [Ollama](https://docs.ollama.com/api/chat)에 있다.
