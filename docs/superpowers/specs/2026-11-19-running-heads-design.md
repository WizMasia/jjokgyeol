# 참고 머리글·바닥글과 자동 쪽 번호

참고 보고서에서 머리글과 바닥글을 골라 문구와 위치를 고친 뒤, 저자가 쓰고 있는 마크다운 원고로 PDF를 만든다. 예를 들어 참고 문서의 `2025 사업보고서`를 `2026 사업보고서`로 고치고, 아래 가운데에는 `－ {현재쪽} －`를 둔다. 편집기에 보이는 미리보기와 다운로드에는 같은 조판 결과를 사용한다.

## 선택한 적용 범위

저자는 **문서 공통값과 제목 구간별 변경**을 선택했다. 표지에서는 공통 바닥글을 숨기고, 부록에서는 머리글 문구만 바꾸면서 공통 쪽 번호를 쓸 수 있다. 함께 검토한 문서 공통 양식과 첫 쪽 표시 스위치 방식은 한 가지 양식을 쓰는 보고서에는 간단하지만, 중간에서 시작하는 부록의 머리글을 지정하기 어렵다.

- 제목 대상은 기존의 고유 마크다운 제목 경로를 사용한다. 공통값, 상위 제목, 하위 제목 순으로 직접 지정한 속성을 적용한다. 머리글과 바닥글은 각각 상속·변경·숨김을 설정하고 다시 상속으로 돌릴 수 있다. 규칙 대상이 사라지거나 중복되면 기존 다시 연결 흐름을 쓴다.
- **물리적 쪽의 첫 원고 줄**이 속한 구간으로 그 쪽의 위·아래 양식을 결정한다. 앞 장의 끝과 부록 제목이 한 쪽에 함께 있으면 그 쪽은 앞 장 양식을 쓰고, 부록 문단이 다음 쪽 첫 줄로 이어지면 부록 양식을 쓴다. 부록 제목 자체가 첫 줄이면 그 쪽부터 부록 양식을 쓴다. 각주만 이어지는 쪽은 직전 원고 구간을 이어받는다. 제목 이전 글은 문서 공통값을 쓴다.
- 번호는 최종 PDF의 첫 쪽을 1로 세며 구간 사이에서도 연속된다. 바닥글을 숨긴 표지가 첫 쪽이면 다음 쪽에 2를 표시한다. 구간은 조판으로 쪽이 늘거나 줄어도 같은 제목을 따라간다.

표시 여부와 칸 내용은 따로 상속한다. 부모가 숨긴 바닥글에서 자식이 왼쪽 문구만 고치면 숨김이 계속된다. 자식에서 ‘표시’를 선택하면 왼쪽 문구와 상속된 가운데 쪽 번호가 함께 나타난다. 가운데 칸을 직접 비우면 빈칸을 저장하고, ‘상속’으로 되돌리면 부모 값이 복원된다. 사용자가 꺼진 영역에 참고 문구를 가져오면 검토 화면이 해당 영역의 ‘표시’도 함께 제안하고 시험 조판 전에 이를 보여 준다.

## 편집과 저장

공통 양식을 직접 편집하거나 **참고 문서 서식 가져오기**에서 후보를 골라 같은 편집기로 연다. 머리글·바닥글 각각에 왼쪽·가운데·오른쪽 한 줄 칸을 두고 문구와 `{현재쪽}`을 조합한다. 숫자를 직접 쓴 `2026`은 고정 문구다. 중괄호 자체는 기존 목록 표현식과 같이 `{{`와 `}}`로 입력한다. 알 수 없는 필드는 오류 위치를 보여 준다.

한 영역 안의 세 칸에는 같은 글꼴·크기·색을 적용한다. 세로 위치는 종이 위쪽 끝에서 머리글의 위쪽까지, 아래쪽 끝에서 바닥글의 아래쪽까지의 거리(mm)로 조정한다. 기본값은 출판 설정에서 읽는다. 양식 JSON에는 저자가 확정한 문구·번호 표현식·위치·서식·제목 경로를 저장한다. 길이는 기존 정수 sp 단위를 쓰며 원고는 마크다운으로 보관한다. 기존 양식 파일에서 머리글·바닥글 값이 생략된 경우 두 영역은 꺼져 있다.

참고 파일의 여러 구간이나 변형에서 값이 다르면 근거를 보고 사용할 후보를 선택한다. 가져온 머리글만 적용해도 기존 바닥글은 이어진다. 후보의 문구를 고친 뒤 현재 원고로 시험 조판하고, 적용·취소·양식 저장·다시 열기에 기존 편집기의 동작을 사용한다. 확인한 머리글·바닥글 문구만 출판 양식의 일부가 된다.

기존 제품 스펙에서 참고 원문을 분석 근거로 한정한 규칙에는 이 명시적 선택만 예외로 둔다. 참고 본문·이미지·분석 근거는 저장 대상에서 제외한다. 원본에 문자 그대로 적힌 `{현재쪽}`은 `{{현재쪽}}`으로 제시해 일반 글자라는 뜻을 보존한다.

## 입력에서 얻는 근거

| 참고 파일 | 문구와 자동 번호 후보 |
|---|---|
| DOCX | 구역이 참조하거나 앞 구역에서 이어받은 머리글·바닥글 파트를 읽는다. 일반 글자와 실제 `PAGE` 필드(단순 필드 및 여러 run에 나뉜 필드)를 구별한다. 필드의 저장된 표시값이 17이어도 후보는 `{현재쪽}`이다. |
| HWPX | 머리말·꼬리말의 하위 문단과 쪽 번호 제어 요소를 읽는다. 문서의 자동 쪽 번호 위치 설정도 후보로 다룬다. 문구·번호·정렬의 근거를 해당 구역과 연결한다. |
| 텍스트 PDF | 같은 상단·하단 위치의 문구를 쪽 사이에서 비교한다. 일정한 접두·접미 문구 사이에서 숫자가 실제 쪽 진행과 함께 변하면 자동 번호로 제안한다. 매 쪽 반복되는 연도는 고정 문구로 보존한다. |
| 스캔 이미지·이미지형 PDF | 연결된 비전 모델이 위·아래 영역과 보이는 문구를 제안하고 저자가 고쳐 쓴다. 한 장의 숫자나 불분명한 판독은 ‘확인 필요’로 표시하고, 저자가 고정 숫자와 자동 번호 중 하나를 정한다. |

위치·서식은 읽을 수 있는 속성별로 제안하고 불확실한 값은 추정 또는 확인 필요로 표시한다. 첫 쪽 전용·홀짝 쪽용 원본은 출처가 구분된 후보로 제시해 저자가 적용 대상을 고른다. 복잡한 표, 그림, 여러 줄 구성, 전체 쪽 수 등의 필드는 조정이 필요한 부분을 표시한다. 저자는 한 줄 문구나 지원하는 번호 표현식으로 고쳐 적용할 수 있다.

DOCX 검증 표본에는 서로 다른 관계 ID의 기본·첫 쪽 머리글을 넣는다. 텍스트 PDF를 한 쪽만 다시 분석해도 앞서 여러 쪽에서 확인된 번호 근거와 저자의 선택을 보존한다. 다른 결과가 나오면 근거와 함께 다시 선택할 수 있게 한다.

## 실제 조판과 검증

LuaLaTeX가 쪽 나눔을 확정할 때 실제 쪽 번호와 그 쪽의 구간을 사용한다. 상·하단 문구는 본문 좌우 경계에 맞추고 기존 위·아래 여백 안에 둔다. 선택한 글꼴의 실제 폭과 높이로 칸 사이 겹침과 여백 초과를 검사한다. 자릿수가 늘어난 쪽에서 넘치면 해당 영역을 알려 문구·크기·여백을 조정할 수 있게 한다. 문구는 글자로 출력하며 저장·열기·직접 설정·참고 후보 적용에 같은 양식 검증기를 사용한다.

양식 JSON은 원고와 별개로 문법·속성값을 검증한다. 특정 원고의 10쪽에서만 칸이 겹치면 시험 조판은 해당 쪽·영역의 오류로 끝나고 시험 적용은 보류된다. 확정 미리보기는 직전의 정상 PDF를 유지한다. 현재 상태를 새로 조판하는 다운로드도 같은 오류를 표시한다.

- 직접 만든 DOCX·HWPX와 같은 내용을 담은 PDF·스캔으로 가져오기를 시험한다. 고정 연도와 자동 번호가 함께 있는 예에서 기관명을 고치고, 참고 문구가 원고 본문에 섞이지 않는지 확인한다.
- 표지·본문·부록이 있는 원고의 중간에 내용을 추가해 추적할 문장이 9쪽에서 10쪽으로 이동하게 한다. 변경 전후의 모든 쪽에서 본문, 윗문구, 아랫번호를 좌표로 구분해 기대값과 대조한다. 제목이 쪽 중간에 있는 경우, 제목이 첫 줄인 경우, 긴 문단이 다음 쪽으로 이어지는 경우를 포함한다.
- 구간별 숨김·상속 복귀, 양식 저장·재개방, 오류·취소 시 직전 확정 PDF 보존을 실제 편집기에서 확인한다. 미리보기와 다운로드 PDF가 바이트 단위로 같은지 확인하고, 머리글·바닥글을 끈 기존 양식의 줄바꿈·글자·각주 좌표를 비교한다.
- 머리글·바닥글만 켜도 본문과 각주 지면이 보존되는지 검사한다. 코드 펜스 뒤 밑줄형 제목이 기존 인쇄 줄에서 갈라지는지도 대조한다. 한 쪽이 A장으로 시작해 B장으로 끝나고 이어서 각주 전용 쪽이 오면, 각주 전용 쪽은 직전 마지막 원고 줄이 속한 B장 양식을 쓴다.
- 최종 Docker 이미지로 시험하고 적용 전후 PDF·원고·양식과 독립 검증 기록을 남긴다. 구간을 물리적 페이지에 연결하는 TeX 구현 기법과 내부 자료 구조는 구현 담당자가 결정한다.
