# 보고서의 마크다운 표 조판

## 사용자 동작

보고서의 머리행, 구분행, 데이터 행으로 작성한 파이프 표를 기존 원고 그대로 열고 갱신한다. 웹·Mac 미리보기, 다운로드한 PDF, 다시 연 쪽결 문서에서 같은 표를 읽을 수 있어야 한다. 원고 제목 뒤의 빈 줄과 다음 제목 앞의 빈 줄 사이에 쓴 `2026. 11. 23.  작성자`가 세 단계 번호 목록으로 바뀌는 오류는 같은 파서에서 별도로 수정하고 검증한다.

## 조판 방식

화면에서 HTML 표를 그리는 방식은 화면에서 빨리 확인할 수 있으나 PDF와 쪽 나눔이 달라진다. 공통 마크다운 파서와 LuaLaTeX 조판기에 표 블록을 추가하는 방식을 권한다. 기존 마크다운 라이브러리의 파이프 표 문법을 사용한다. 서로 열 개수가 맞는 머리행과 구분행으로 표를 인식한다. 일반 문장 안의 세로줄과 예시 코드의 세로줄은 글자로 남긴다. 이스케이프한 세로줄, 빈 셀, 셀 안의 강조와 열 정렬을 보존한다. 원고·양식과 저장 형식은 기존 계약을 따른다.

본문 폭 안에 표를 맞춘다. 날짜나 구분처럼 짧은 열은 좁게 두고 긴 설명에 나머지 폭을 배분한다. 긴 한글은 셀 안에서 줄을 바꾸고, 폭을 넘는 긴 낱말도 처리한다. 머리행은 굵기와 가로선으로 구분한다. 표가 다음 쪽으로 이어지면 열 제목을 반복한다. 보통 행은 함께 옮기고, 한 쪽보다 긴 행은 내용을 이어서 보여준다. 모든 셀은 선택·검색·복사가 가능한 PDF 텍스트여야 한다. 기본 모양과 폭 산정 방식은 구현자가 정한다.

규칙·모델 조판에서 동일한 표를 사용한다. 본문에 디시전 모델이 적용되어도 표의 셀, 정렬, 쪽 나눔은 조판기가 맡는다. 표는 셀마다 줄 수가 다르므로 여백 줄 번호를 소비하지 않는다. 반복 머리행도 같은 정책을 따르고, 표 다음의 일반 문단에서 번호가 이어진다. 기존 문서 글꼴과 한글 대체 글꼴을 사용한다. 입력 문자열은 기존의 안전한 텍스트 출력 경로를 사용한다.

## 확인할 결과

- 화면에 나온 날짜·설명 형태의 짧은 표와 여러 쪽짜리 표를 웹과 Mac에서 실제 PDF로 검증한다. 두 열의 시작 좌표, 셀 줄바꿈, 반복 머리행, 모든 데이터 행의 순서와 끝 문장을 확인한다.
- 한 셀이 한 쪽보다 긴 원고와 표 다음에 본문·목록이 있는 원고에서 누락·겹침을 확인한다.
- 일반 문장, 실제 번호 목록, 표를 포함하지 않은 기존 기준 원고를 비교한다. 표가 들어간 원고도 쪽결로 저장하고 다시 조판한다.
