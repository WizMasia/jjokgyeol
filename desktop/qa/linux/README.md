# Linux x86_64 development verification

`.github/workflows/native-linux.yml` runs independently on pushes to `feature/native-desktop`. The Ubuntu 24.04 job installs development dependencies, uses Python 3.12 and `npm ci`, builds the frontend, runs both locked Rust crate test suites, builds the Tauri GTK/WebKit executable, and requires its own mapped window under Xvfb with Openbox. The smoke check matches the exact UTF-8 title and process ID using X11 properties and checks IsViewable. On failure it saves the X11 window tree, per-window properties and state, process status, application and window-manager stderr, and an XWD screenshot. The smoke test opens the settings window through the accessibility interface, closes it and checks that the editor window remains open.

The separate Debian amd64 container uses the existing Dockerfile `engine` target and its installed TeX Live and Nanum fonts. It builds the PyInstaller worker and Rust CLI inside that container, runs the numbering fixture through both, and compares its PDF against `proofs/numbering/odd-even.pdf` with the existing geometry comparator. The calibration uses the container’s TeX tree and libraries. A separate release job builds the Ubuntu 24.04 x86_64 DEB and verifies the installed application and bundled typesetter. [Installer and verification procedure](../../release/README.md)

Logs and the generated PDF are retained as separate GitHub Actions artifacts for seven days, accessible according to repository Actions permissions; use a private repository for private artifacts. Artifacts may be incomplete when a step fails.

Run the portable smoke helper test with `python -m unittest discover -s desktop/qa/linux -p 'test_*.py'`. On a Docker host, build the engine target and mount the checkout read-only at `/src` and a writable results directory at `/results`, then run `sh /src/desktop/qa/linux/proof.sh` with `--platform linux/amd64`. On arm64 this may be emulated and is not a native x86_64 performance or launch check.
