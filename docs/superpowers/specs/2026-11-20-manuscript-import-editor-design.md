# T10 원고 가져오기 HTTP·편집기 보충 설계

기존 [변환 계약](2026-11-20-manuscript-import-design.md)에 따라 편집자가 원본 하나를 선택하면 같은 이름의 새 마크다운 원고를 연다. 변환 완료 전까지 편집 중인 원고, 저장 이름, 직전 미리보기를 유지한다. 미리보기 갱신과 PDF 다운로드는 기존 동작을 따른다.

## 접근 방식과 위임 결정

추천 1안을 채택했다. **원고 가져오기**를 별도 선택기로 두고, 마크다운 열기와 같은 `openFile("source", …)` 경로에서 성공한 최신 응답만 적용한다. 선택기를 합치는 안도 가능하지만 기존 UTF-8 마크다운 열기는 BOM과 혼합 줄바꿈을 그대로 보존하는 용도가 있다. 별도 선택기는 원본에서 새 파일을 만든다는 점을 동작 이름으로 알려 준다.

- `POST /api/import?name=파일명`은 파일 바이트를 직접 받는다. 응답은 `markdown` 문자열과 `warnings` 문자열 배열이다. 파일명은 판독기에만 전달하고 서버의 파일 경로로 쓰지 않는다. 입력 오류는 422, 크기 초과는 413, 포화는 429, 기한 초과는 504를 사용한다.
- `DocumentJob`과 `isolated_job`이 개인 작업 폴더, 프로세스 그룹, 연결 해제, 응답 전송 완료까지의 슬롯과 기한을 관리한다. 업로드 한도는 변환 라이브러리의 `imports.json`에서 읽는다. 서버 운영 설정의 조판 슬롯·초 단위 기한, 기존 문서 분석 작업자의 Linux 메모리 한도와 작업 파일 한도를 공유한다.
- 편집기는 TXT, HTML, DOCX, HWPX, HWP 파일을 선택하고 변환 결과의 이름을 마지막 확장자만 바꿔 정한다. 성공 시 기존 출판 양식으로 편집·저장·조판할 수 있다. 변환 경고는 원고 옆에 텍스트 목록으로 제공한다. 열기 실패나 취소된 응답은 원고·파일명·경고를 교체하지 않는다.
- 변환·구조 보존은 라이브러리 담당 범위다. 다섯 실물 파일을 일반 파일 선택기로 열고 원본 바이트, 기대 본문, 새 원고 다운로드와 실제 PDF에 남은 문구를 대조한다.
