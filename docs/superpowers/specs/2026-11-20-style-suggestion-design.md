# T12 자연어 양식 제안

저자가 출판 양식에서 “본문은 16pt로 하고 바닥글 가운데에 쪽 번호를 넣어 줘” 또는 “본문만 16pt로”라고 요청한다. 편집기는 변경 항목과 값을 보여 준다. 적용 전에는 원고·양식·PDF가 그대로다. 적용 후 본문을 14pt로 직접 고쳐도 가운데 쪽 번호가 유지된다. 본문만 요청하면 설정한 제목 크기와 여백을 보존한다. 이전 양식에서 생략한 제목 크기는 T7의 기존 배율 계약을 따른다.

## 설계 결정

- 위임받은 1안은 로컬 LM Studio의 구조화된 필드 제안을 기존 `Style`로 검증하는 것이다. 키워드로 예문을 분기하는 방식은 자유로운 요청에 대응하기 어렵고, 모델이 양식 전체를 재작성하면 기존 구간 서식을 잃을 수 있다.
- 서버가 지정한 모델에는 요청과 제안 가능한 현재 양식 값만 전달한다. 출판 단위로 본문·글꼴·판형·여백·간격, 기존 목록 단계의 표지·거리, 문서 공통 머리글·바닥글 칸을 다룬다. 쪽 번호는 `{현재쪽}`으로 저장하고 칸에 문구를 넣으면 그 영역을 표시한다. 구간별·홀짝별 규칙과 같은 영역의 다른 칸을 보존한다.
- `suggest_patch(request, current)`는 기존 `apply_style`로 한 번에 검증한 편집 단위 patch를 돌려준다. 알 수 없는 필드, 중복 지시, 잘못된 목록 표현식, 불가능한 여백은 전체 제안을 거부한다. 모델 주소와 이름은 운영자 설정이다.
- `POST /api/style-suggestion`은 `{"request": "...", "style": {...}}`를 받아 `{"patch": {...}}`를 반환한다. 운영 한도로 업로드, 모델 응답 크기, 생성 토큰, 동시 작업 수, 전체 시간을 제한한다. 각 작업의 임시 디렉터리와 프로세스는 기존 조판 작업 감독기를 쓴다.
- 제안을 취소하거나 같은 양식을 편집하는 동안 늦은 응답이 와도 저자의 편집을 보존한다. 요청 시점의 양식과 현재 값이 다르면 다시 요청하게 한다. 원고만 수정한 경우에는 그 원고를 유지하며 제안을 적용할 수 있다. 미리보기와 다운로드는 기존 편집기 경로를 쓴다.

## 인수

오프라인 모델 대역으로 부분 변경·오류·편집 경합을 반복 검사한다. 두 예문은 선정한 실제 모델과 정상 편집기·API에서도 실행하고, Linux ARM64 LuaLaTeX 출력의 글자 크기·여백·쪽 번호 위치를 읽는다. 부모 작업자가 커밋을 독립 검토한다.
